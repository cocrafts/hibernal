# Workarounds in the std/solana port

Each row is a place where Hibernal goes around a gap instead of waiting for its root fix. Removing a row means doing what its last column says.

| Where | Workaround | Root fix | Remove when |
|---|---|---|---|
| every build of `program/` | built with the private `/Users/le/metascript/.hibernal-msc/bin/msc` (BUILD `3db21860` = recompiler `36251885` + lane A `bca987c4` + std/solana up to `28856eb9`, branch `wt/hibernal-msc`, never landed); `~/.metascript` stays `013853dd` | the same commits land on recompiler `main` and are synced to `~/.metascript` | the installed `msc` contains them: build with plain `msc`, delete `/Users/le/metascript/.hibernal-msc` |
| `program/main.ms` and every handler using `args<T>()` | `selectInstruction` and `readArgs` imported beside the `instruction`/`args` macros | compiler card `2026-10-01-bindsym-of-a-generic-function-crashes-msc` (std/solana `STD-SOLANA.md` §9) | the card closes: drop the extra imports |
| `program/test/owner.ms`, `program/test/payout.ms` | account bytes are built and read by one host-run staging entry per account type (`stagePetEntry`, `seeLedgerEntry`, …) instead of one generic `encoded<T>`/`decoded<T>` | `Ptr<T>` dereferenced with `at[]` inside an instantiated generic function types as `Ptr<T>`, not `T` (card `~/metascript/.inbox/compiler/2026-10-02-generic-ptr-deref-keeps-the-pointer-type.md`, repro `/tmp/hibStd/repros/generic-ptr-deref/repro2.ms`) | the deref types as `T`: fold the per-type entries into one generic pair |
| `program/day.ms` `loadedPets`, `deadWilds` | heap memory through `@include("runtime/solana/solana.h")` + `extern function msSolAlloc` (ten `Pet`s do not fit the 4 KB SBF frame) | a public allocation API in std/solana (asks card row 17, not covered) | std/solana exports an allocator: replace the extern |
| `program/day.ms` `seededInstruction` | the `Seeded` discriminator comes from a function typed `Discriminator`; an untyped `const x = @comptime { return instructionDiscriminator(...); }` becomes a heap `int32` array and fails on SBF with `Overlapping copy` | compiler: an untyped `@comptime` struct keeps its declared type (card `~/metascript/.inbox/compiler/2026-10-02-untyped-comptime-struct-becomes-an-anonymous-heap-object.md`, repro `/tmp/hibStd/repros/comptime-untyped-struct/`) | the untyped form emits `Discriminator`: inline it |
| `program/brain.ms` | observation and logit buffers are literal-sized (`int32[46]`, `int32[32]`, …) and `buffersMatchRules()` checks the literals against the rules constants at run time | lane B sized arrays (`T[CONST]`, recompiler `wt/sized-arrays`) | lane B is in the build: size from the rules constants, delete `buffersMatchRules` |
| `rules/actions.ms` `settleAttack` | split into exported `openingAgainst`, `attackerWon`, `bittenBy`, `defenderHeld` (exported so clang does not inline them back): msc's aggregate temporaries gave `settleAttack` a 6,720-byte SBF frame (maximum 4,096); msc dropped clang's frame error because clang exits 0 (fixed in `3db21860`, the build now fails loud), and the first won fight failed on LiteSVM with `Overlapping copy`; behaviour and every `sim/determinism.ms` digest unchanged | compiler: emit fewer aggregate temporaries (card `~/metascript/.inbox/compiler/2026-10-02-sbf-frame-grows-with-aggregate-temporaries.md`, repro `/tmp/hibStd/repros/sbf-frame-overflow-hidden/`) | msc keeps `settleAttack` under 4,096 bytes as one function and reports overflow: fold the helpers back if wanted |
| `rules/layout.ms` `FightRecord.outcome` | stored as `uint8` and read through `fightOutcome()`, because an `Outcome` field is a 4-byte C enum with no Anchor IDL type and `enum Outcome: uint8` does not parse | compiler card `2026-10-01-enum-storage-width` (std/solana `STD-SOLANA.md` §9) | `enum Outcome: uint8` parses: type the field as `Outcome`, drop `fightOutcome()` |
| `program/hydra.ms` | Hydra `Create`/`Cancel` built byte by byte with `Instruction` (template metas, one-shot schedule, CU limit) | std/solana Hydra helpers, the way `std/solana/vrf` wraps VRF | std/solana exports crank create/cancel: call them, delete the byte layout here |
| `program/payout.ms` `paidCommit` | `ScheduleCommit` through the vrf-payer PDA built by hand and signed with `invokeSigned`, because std's `commit(…, feeVault)` calls `invoke()` and needs a real signer | std/solana `commit` overload signed with seeds | the overload exists: call it, delete `paidCommit` |
| `tools/chain/cranker.sh` | `hydra-cranker` 0.2.0 is restarted every `CRANKER_RESTART_SECONDS` (300) and whenever it exits: its cache never drops a crank that `Sweep` closed (the ER sends no `programSubscribe` notification for an account leaving Hydra), so its per-slot scan grows with every spent crank. Measured: after a 50k re-sort the cranker sat at 90% CPU firing 14–40 triggers/s; restarted it cached 5,006 live cranks and fired ~485/s at 14% CPU | MagicBlock: the cranker drops a crank once it is exhausted (`remaining` 0) or the ER notifies closed accounts. The game runs its own `tools/chain/gameCranker.mjs`, which keeps no Hydra cache, and keeps this one only as a backup | the cranker evicts spent cranks: run the binary directly again |
| `program/admission.ms` `delegatePet` | the Pet's mint is copied to a local before `delegate`: std's `delegateAt` zeroes the delegated data and then signs with seeds that pointed into it, so devnet failed every DelegatePet with `PrivilegeEscalation` | std/solana copies or rejects seeds inside the delegated account (card `~/metascript/.inbox/compiler/2026-10-09-std-solana-delegate-at-zeroes-the-seeds-it-signs-with.md`) | `delegateAt` no longer reads seed bytes after zeroing: pass `record.mint` directly |
